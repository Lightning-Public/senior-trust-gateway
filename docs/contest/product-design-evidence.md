# Product Design Evidence — 시니어 AI 생활매니저

Last updated: 2026-09-06

## 목적

공모전 제출을 위한 내부 검증은 별도로 관리하되, 실제 사용자 화면은 **완성된 제품의 언어와 경험**으로 보여야 한다.

`시니어 AI 생활매니저`가 `안심매니저` 또는 문자 검사 도구로 축소돼 보이지 않고, 제품 정체성을 첫 진입부터 메인 화면까지 일관되게 전달하도록 UI/UX 구조를 정리한다.

## 디자인 원칙

1. 첫 10초 안에 서비스 역할을 이해할 수 있어야 한다.
2. 현재 실제 사용할 수 있는 기능은 메인 최상단에 크게 배치한다.
3. 긴급하거나 위험한 행동은 일반 기능보다 먼저 보여준다.
4. 아직 제공하지 않는 기능은 제품 언어인 `준비 중`으로 표현한다.
5. 시니어 사용성을 위해 큰 글자, 큰 터치 영역, 적은 선택지, 높은 대비, 충분한 여백을 유지한다.
6. 기술 기능명이 아니라 사용자가 도움받는 생활 장면을 중심으로 설명한다.
7. 브랜드 요소는 신뢰를 해치지 않는 작은 동행자 표식으로 반복 노출한다.
8. 사용자 화면과 내부 개발/공모전 문서를 명확히 분리한다.

## 사용자 화면 금지 언어

아래 표현은 내부 문서에서만 사용하고 제품 UI에는 표시하지 않는다.

- 공모전 / 출품 / MVP
- 프로토타입 / 데모 / 시연
- 실제 구현 / 구현 완료 / 구현 상태
- 확장 방향

제품 화면에서는 다음 표현을 사용한다.

- 현재 제공: `바로 이용 가능`, `지금 이용`, `이용 가능`
- 향후 제공: `준비 중`
- 제한사항: 사용자에게 필요한 사실만 자연스럽게 설명
  - 예: `개인정보는 대신 입력하거나 저장하지 않습니다.`

심사위원에게 보여주는 화면도 사용자에게 실제 배포할 제품 화면과 동일한 기준으로 작성한다.

## 첫 진입 온보딩

현재 제품에는 실제 로그인 기능이 없다. 로그인 화면을 가장하지 않고 **첫 진입 시 2단계 온보딩**을 제공한다. 향후 인증 기능이 생기면 동일한 온보딩을 로그인 직후 연결할 수 있다.

### 1단계 — 생활 도움 인지

> 어려운 디지털 생활을 옆에서 같이 봐드려요

- 문자·카톡
- 병원 접수
- 생활 도움

### 2단계 — 안전 원칙 인지

> 위험한 순간에는 먼저 멈추겠습니다

`쉽게 이해 → 위험 확인 → 다음 행동 → 사람 확인`

첫 확인 여부만 브라우저 localStorage에 저장하며 개인정보·계정정보는 저장하지 않는다. 메인 상단의 `처음 안내` 버튼으로 다시 볼 수 있다.

## 메인 화면 우선순위

### 1. 긴급 도움

가장 먼저 다음 메시지를 노출한다.

> 링크·송금·인증번호는 잠깐 멈추세요

사용자는 바로 Trust Check로 이동할 수 있다.

### 2. 빠른 도움 — 현재 제공 기능

현재 제공되는 기능 두 개를 가장 큰 카드로 배치한다.

- 문자·카톡 같이 보기
- 병원 접수 도움

즐겨찾기 저장/개인화 자체는 이번 범위에서 새 기능으로 추가하지 않는다. 대신 향후 즐겨찾기/사용빈도 기반 정렬을 수용할 영역을 `빠른 도움`으로 구조화한다.

### 3. 생활 도움 영역

- 예약·일정 챙기기 — `준비 중`
- 행정·생활 지원 — `준비 중`
- 가족·사람 연결 — `안전 원칙`

아직 제공하지 않는 기능이 현재 사용 가능한 기능처럼 보이지 않도록 상태를 구분하되, 개발 로드맵 용어를 사용자에게 직접 노출하지 않는다.

## 브랜드 요소

별도 이미지 파일 없이 CSS 기반 `동행 마크`를 사용한다.

- 둥근 말풍선/동행자 실루엣
- 단순한 눈과 미소
- 작은 포인트 점
- 온보딩, 앱 헤더, 장기 제품 방향 영역에 반복 노출

목표는 캐릭터 상품화가 아니라 **서비스명을 기억하게 해주는 작은 시각 앵커**다.
