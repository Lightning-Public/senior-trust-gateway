# aitestbed 플랫폼 활용 증빙 Runbook

Last updated: 2026-09-05

## 목적

이 문서는 **이미 존재하는 `senior-trust-gateway` MVP를 대신 만들기 위한 개발 계획이 아니다.**

목적은 2026 모두의 AI 실험실 공모전 제출에 필요한 **aitestbed 실제 활용 증빙**을 확보하는 것이다.

MVP 정본:

> `Lightning-Public/senior-trust-gateway`의 실행 가능한 prototype

공모전 최상위 하네스:

> `docs/contest/contest-harness.md`

## 역할 경계

### MVP가 담당

- Trust Check 실제 실행
- LOW/MEDIUM/HIGH 안전정책
- 쉬운 다음 행동
- Hospital Kiosk Safe Guidance
- HIGH 안전 중단과 사람 도움 안내

### aitestbed가 담당

- 플랫폼 사용 사실 증빙
- 바이브코딩 생성/수정 경험 증빙
- 생성 결과 화면 캡처
- 생성 소스 다운로드 가능 여부 확인
- 필요하면 UI 아이디어를 현재 MVP와 비교

aitestbed 생성 결과는 **현재 MVP의 정본이 아니며**, 기존 안전정책·아키텍처·코드를 교체하지 않는다.

## 사실 경계

### Confirmed

- `AitestbedVibeWorkflow`: 바이브코딩 생성·수정·소스 다운로드·공모전 증빙
- 사용자의 aitestbed 로그인 및 클라우드 신청 화면 진입

### Unverified

- 외부 AI 추론 API base URL
- 인증 방식
- 모델 목록과 quota
- request/response schema
- image input
- 외부 프로젝트 runtime 호출

`AitestbedModelApiProvider`는 공식 호출 계약과 실제 probe 전에는 구현하지 않는다.

## 가장 짧은 증빙 절차

1. aitestbed에서 새 바이브코딩 프로젝트를 만든다.
2. 프로젝트명은 `시니어 AI 생활매니저`로 사용한다.
3. 현재 MVP와 같은 핵심 흐름을 설명하는 짧은 프롬프트를 입력한다.
4. 생성 결과 화면을 캡처한다.
5. 소스 다운로드 기능이 보이면 다운로드한다.
6. 다운로드 소스는 현재 MVP와 비교하되 **필요한 UI 개선만 후보로 본다.**

이 절차가 MVP 개발의 선행조건은 아니다. MVP 개발과 제출문서 정리는 계속 현재 저장소에서 진행한다.

## 플랫폼 증빙용 프롬프트

```text
프로젝트명: 시니어 AI 생활매니저

60대 이상 사용자를 위한 모바일 우선 단일 페이지 프로토타입을 만들어 주세요.

핵심 서비스는 하나의 시니어 AI 생활매니저이며 다음 두 생활 장면을 보여줍니다.

1. Trust Check
- 받은 문자나 디지털 요청을 입력
- 무슨 뜻인지 쉬운 설명
- 위험 확인: LOW / MEDIUM / HIGH
- 지금 할 안전한 행동
- 필요하면 가족/사람 확인
- HIGH에서는 계속 진행하거나 송금·인증정보 제공을 승인하지 않음

2. Hospital Kiosk Safe Guidance
- 병원 접수 시작
- 예약 진료 선택
- 민감정보 입력 단계에서는 HIGH로 멈춤
- 주민등록번호를 대신 입력하거나 저장하지 않음
- 직원 도움을 요청하도록 안내

공통 흐름은
“이해 → 위험 확인 → 쉬운 다음 행동 → 필요 시 사람 연결”
입니다.

큰 글씨, 큰 버튼, 고대비, 충분한 여백을 사용하세요.
카메라/CV/OCR, 결제, 실제 사람 호출, 외부 AI API endpoint를 구현했다고 가정하지 마세요.
```

이 프롬프트의 목적은 **플랫폼 활용 증거 확보**이며, 생성 결과를 그대로 제품 코드로 채택하기 위한 것이 아니다.

## 캡처할 증빙

최소 3개:

1. 프로젝트명 `시니어 AI 생활매니저`가 보이는 화면
2. 위 프롬프트를 입력한 화면
3. 생성 결과 화면

가능하면 추가:

- Hospital Kiosk 화면
- 소스 다운로드 버튼/결과
- 실제 화면에 모델명이 표시되는 경우 그 정확한 문자열

개인정보·API 키·토큰은 캡처하지 않는다.

## 다운로드 소스 처리

다운로드 결과가 확보되면 다음 순서로만 본다.

1. 현재 MVP와 UI 차이 비교
2. 접근성/레이아웃 개선 후보 추출
3. 기존 안전정책과 충돌 여부 확인
4. 필요한 UI만 최소 포팅

### 가져올 수 있는 것

- 큰 버튼/큰 글씨
- 여백/고대비
- 결과 카드 배치
- 병원 Kiosk 단계 표현
- 포인터/안내 UI

### 가져오지 않는 것

- 추정된 AI endpoint
- client-side API key
- AI가 위험등급을 결정하는 코드
- HIGH 하향 로직
- 개인정보 저장
- 확인되지 않은 CV/OCR
- 현재 RuleBased/Grounded 안전 로직을 교체하는 코드

## 완료 조건

이 runbook은 다음이 확보되면 완료다.

- 플랫폼 사용 화면 3개 이상
- 실제 입력 프롬프트
- 생성 결과
- 가능하면 다운로드 소스 또는 다운로드 기능 증거

그 다음 즉시 **MVP/제출문서 완성 작업으로 복귀**한다.
