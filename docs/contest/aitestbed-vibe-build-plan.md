# aitestbed 바이브코딩 프로토타입 생성 계획

Last updated: 2026-09-05

## 목적

모두의 AI 실험실 바이브코딩에서 공모전 증빙용 `시니어 AI 생활매니저` 프로토타입을 생성하고, 생성 소스를 다운로드한 뒤 현재 `senior-trust-gateway`와 비교해 필요한 UI만 최소 포팅한다.

이 문서는 **AitestbedVibeWorkflow** 사용 계획이다. 외부 프로젝트에서 aitestbed 모델을 호출하는 `AitestbedModelApiProvider` 사용 가능성을 전제로 하지 않는다.

## 사실 경계

현재 confirmed:

- 바이브코딩으로 프로토타입 생성·수정
- 생성 소스 다운로드
- 생성 과정/결과의 공모전 증빙 활용

현재 unverified:

- 외부 AI 추론 API base URL
- 인증 방식과 request/response schema
- 실제 모델 목록과 quota
- image input
- 외부 프로젝트에서의 런타임 호출

따라서 아래 생성 프롬프트는 외부 AI endpoint, API key, CV/OCR를 만들거나 추정하도록 요구하지 않는다.

## 생성할 화면 구조

### 장면 1 — Trust Check (메인 80%)

한 화면에서 의심 문자나 디지털 요청을 확인한다.

1. 큰 제목: `이 문자, 믿어도 될까요?`
2. 문자 입력 영역
3. 개인정보 없는 예시 3개
   - 일반 일정 안내
   - 택배 외부 링크
   - 검찰 사칭 + 안전계좌 이체
4. 결과 영역
   - `무슨 뜻인가요?`
   - `위험 확인`
   - `지금 이렇게 하세요`
   - `확실하지 않은 점`
5. HIGH이면 `멈추세요`와 `가족/사람에게 확인`을 가장 강하게 표시

위험등급은 AI가 결정하거나 낮추는 것으로 표현하지 않는다. 화면에서는 `규칙 안전판`과 `AI 설명`의 역할을 구분한다.

### 장면 2 — Kiosk Safe Guidance (확장 20%)

`병원 접수` 한 장면만 제공한다.

구조화된 키오스크 화면으로 다음 순서를 보여준다.

```text
진료 접수
→ 예약 진료 선택
→ 본인 확인 정보 입력 화면
→ 민감정보 단계에서 자동 진행 중단
→ 직원 도움 요청
```

- 현재 단계 의미를 큰 글씨로 설명
- 노란 포인터/강조 영역으로 다음 버튼 위치 표현
- 민감정보 단계는 HIGH
- 생활매니저가 주민등록번호를 대신 입력하거나 저장하지 않음
- 카메라/CV/OCR를 구현했다고 표현하지 않음

UX provenance: `Lightning-Public/kiosk_ar_assistant@3a7da8f`의 큰 안내·음성형 문구·포인터 개념을 참조한다.

## aitestbed에 붙여 넣을 1차 생성 프롬프트

아래 블록을 그대로 사용한다.

```text
프로젝트명: 시니어 AI 생활매니저
부제: 안심부터 시작하는 시니어 디지털 동행

60대 이상 사용자를 위한 모바일 우선 단일 페이지 웹 프로토타입을 만들어 주세요.
목표는 문자 피싱 탐지기와 키오스크 앱 두 개를 만드는 것이 아니라, 하나의 생활매니저가 서로 다른 디지털 생활 장면에서
“이해 → 위험 확인 → 쉬운 다음 행동 → 필요 시 사람 연결”
을 보여주는 것입니다.

전체 비중은 Trust Check 80%, Kiosk Safe Guidance 20%로 구성해 주세요.

[장면 1: Trust Check]
- 큰 제목: “이 문자, 믿어도 될까요?”
- 받은 문자 내용을 붙여 넣는 큰 입력창
- 예시 버튼 3개: 일정 안내 / 택배 링크 / 검찰 사칭
- 결과는 큰 카드 4개로 표시:
  1) 무슨 뜻인가요?
  2) 위험 확인
  3) 지금 이렇게 하세요
  4) 확실하지 않은 점
- 위험 표시 문구는 LOW: “위험 신호 적음”, MEDIUM: “확인 필요”, HIGH: “멈추세요”
- LOW도 “안전 확인 완료”라고 표현하지 마세요.
- HIGH에서는 송금·인증정보·앱 설치·민감정보 같은 행동을 승인하거나 계속하라고 하지 마세요.
- HIGH에서는 “가족 또는 믿을 수 있는 사람에게 확인” 행동을 크게 보여 주세요.
- 규칙 안전판이 최종 위험 통제 역할이고 AI 설명은 위험도를 낮출 수 없다는 설명을 작은 문구로 표시해 주세요.

[장면 2: 병원 키오스크 접수 도움]
- 메인 Trust Check 아래에 접을 수 있는 보조 영역으로 두어 비중을 작게 유지해 주세요.
- 카메라나 OCR 없이 사전 정의된 병원 키오스크 화면 구조를 사용하세요.
- 순서:
  1) “진료 접수” 화면에서 “접수 시작”을 노란 포인터로 강조
  2) “접수 방법 선택”에서 “예약 진료”를 강조
  3) “본인 확인 정보 입력”에서 주민등록번호 전체 입력 요청이 나타나는 예시
  4) 이 단계는 HIGH로 표시하고 자동 진행하지 않음
  5) “직원 도움 요청” 버튼을 가장 큰 안전 행동으로 제공
- 주민등록번호나 실제 개인정보를 입력하거나 저장하는 기능은 만들지 마세요.
- “이 데모는 구조화된 화면 안내이며 실제 CV/OCR 인식 기능은 아닙니다”라는 문구를 표시해 주세요.

[디자인]
- 한국어
- 60대 이상 사용자가 보기 쉬운 큰 글씨와 큰 버튼
- 한 화면에 선택지를 너무 많이 보여주지 않음
- 고대비, 충분한 여백
- 색상만으로 위험을 표현하지 않고 텍스트를 함께 사용
- 어려운 AI 용어보다 행동 문구를 먼저 보여 줌

[기술/안전 제약]
- 외부 AI API endpoint를 추정하거나 하드코딩하지 마세요.
- API key나 개인정보 저장 기능을 만들지 마세요.
- 실제 모델 호출이 필요한 부분은 AIProvider라는 교체 가능한 경계가 있다고만 표시하고 기본 프로토타입에서는 네트워크 모델 호출을 만들지 마세요.
- Trust Check 예시 출력은 데모 데이터임을 코드에서 구분할 수 있게 해 주세요.
- HIGH 위험은 AI 설명으로 LOW/MEDIUM으로 변경되지 않게 설계해 주세요.
- 카메라, OCR, 결제, 실제 사람 호출 기능을 완료했다고 표현하지 마세요.

완성 후 소스를 다운로드할 수 있는 구조로 유지해 주세요.
```

## 1차 생성 후 수정 프롬프트

생성 화면이 장황하거나 챗봇처럼 보이면 다음을 사용한다.

```text
전체 기능을 늘리지 말고 현재 화면을 시니어 생활매니저답게 정리해 주세요.
Trust Check를 가장 먼저 보이게 하고 Kiosk는 접힌 보조 장면으로 유지하세요.
텍스트 설명을 줄이고 “지금 할 행동”을 가장 크게 보여 주세요.
HIGH 위험에서 계속 진행하는 버튼은 없애고 사람에게 확인하는 버튼만 남겨 주세요.
AI가 위험을 결정하는 것처럼 보이는 표현은 “AI 설명”과 “규칙 안전판”으로 분리해 주세요.
```

Kiosk가 과도하게 AR/CV 제품처럼 만들어지면 다음을 사용한다.

```text
병원 키오스크 장면에서 카메라, OCR, 실시간 객체 인식 기능을 제거해 주세요.
사전 정의된 키오스크 화면 + 노란 포인터 + 쉬운 안내 문구만 사용하세요.
민감정보 입력 화면에서 HIGH로 멈추고 “직원 도움 요청”으로 끝나는 안전 중단 흐름을 유지하세요.
```

## 생성 소스 다운로드 후 비교 기준

다운로드 결과가 제공되면 현재 TypeScript prototype과 다음 기준으로 비교한다.

### 가져올 후보

- 시니어용 레이아웃 개선
- 큰 버튼/고대비/여백
- Trust Check 결과 카드 구성
- 병원 키오스크 단계 표현
- 포인터/안내 컴포넌트

### 가져오지 않을 것

- 추정한 aitestbed AI endpoint
- client-side API key
- AI가 위험등급을 결정하거나 HIGH를 낮추는 로직
- 실제 개인정보 저장
- 확인되지 않은 CV/OCR
- 현재 `RuleBasedRiskAnalyzer`, `GroundedRiskAnalyzer`를 대체하는 생성 코드

### 포팅 원칙

1. UI/접근성 개선을 우선 비교한다.
2. 기존 안전 로직은 정본으로 유지한다.
3. 생성 코드에 provider 호출이 있으면 공식 계약을 먼저 검증한다.
4. 필요한 컴포넌트만 포팅하고 저장소 전체 구조를 교체하지 않는다.
5. 포팅한 파일마다 aitestbed 생성본에서 가져온 이유와 변경 범위를 PR에 기록한다.

## 캡처해야 할 증빙

최소 3장:

- 프로젝트 생성/프로젝트명 화면
- 위 생성 프롬프트가 보이는 화면
- 생성된 Trust Check 결과 화면

가능하면 추가:

- 병원 Kiosk Safe Guidance 화면
- 소스 다운로드 화면 또는 다운로드 결과 파일 목록

실제 모델명/API/토큰은 화면에서 확인된 경우에만 별도 기록한다.
