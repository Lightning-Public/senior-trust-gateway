# AI 활용 필요성·플랫폼 활용·안전 설계

`시니어 AI 생활매니저`가 해결하려는 문제는 고령자가 문자, 키오스크, 공공·생활 서비스 같은 디지털 환경에서 “이 내용을 믿어도 되는가, 지금 무엇을 해야 하는가”를 매번 스스로 판단해야 한다는 점이다. 기존 규칙엔진은 송금·인증번호·앱 설치·원격제어처럼 명확한 위험 신호를 빠르고 일관되게 차단할 수 있지만, 가족 사칭 가능성, 기관 안내, 복잡한 키오스크 화면처럼 문맥을 이해해야 하는 상황에는 한계가 있다. 따라서 AI는 부가기능이 아니라 **애매한 의도와 상황을 이해하고 60대 이상 사용자가 이해하기 쉬운 설명과 다음 행동으로 바꾸는 생활지원의 핵심 수단**으로 사용한다.

공모전 Phase 0은 전체 생활매니저 가운데 가장 신뢰가 중요한 두 장면으로 범위를 제한한다. 첫째, `Trust Check`는 의심 문자와 디지털 요청의 의도·사칭·압박 맥락을 설명한다. 둘째, `Kiosk Safe Guidance`는 `Lightning-Public/kiosk_ar_assistant@3a7da8f`의 화면·음성·포인터 UX를 활용해 복잡한 키오스크 이용 흐름을 쉽게 안내한다. 두 기능은 별도 앱이 아니라 동일한 흐름인 `이해 → 위험 확인 → 쉬운 다음 행동 → 필요 시 사람 연결`을 공유한다. 단기 제출 범위는 Trust Check 80% + Kiosk 확장 시나리오 20%로 제한해 실현 가능성과 완성도를 확보한다.

서비스는 AI와 안전정책의 역할을 의도적으로 분리한다. Senior Trust Gateway는 위험등급, 공식 검증 수준, 권한정책과 사람 에스컬레이션을 담당한다. aitestbed AI는 공통 `AIProvider`를 통해 문맥 이해와 쉬운 설명을 담당한다. AI 출력은 `summary`, `risk_context`, `safe_next_action`, `uncertainty` 구조로 제한하며, 송금·이체·인증번호 전달·앱 설치·원격제어·개인정보·결제처럼 고위험 행동은 규칙엔진의 HIGH 판정을 AI가 낮출 수 없다. 즉 **AI confidence ≠ user authorization**을 제품 정책으로 구현한다.

모두의 AI 실험실에서는 실제 계정에 제공되는 모델과 토큰·API 방식을 화면에서 확인한 뒤 `시니어 AI 생활매니저` 프로젝트를 실증한다. 모델/API 호출이 가능하면 서버 측 `AitestbedProvider` 뒤에 연결하고, API 키는 브라우저 번들·Git·로그에 넣지 않는다. 모델 장애, quota 초과, 응답 지연, 잘못된 JSON, 모델 거부가 발생하면 AI 결과를 버리고 결정론적 규칙과 기존 안내로 fallback한다. 문자 원문과 키오스크 화면의 개인정보는 최소화·마스킹하며, image input 등 확인되지 않은 기능은 실제 계정에서 지원이 확인되기 전에는 구현 완료로 주장하지 않는다.

이 구조는 공모전의 **문제 정의 및 제안 필요성**에는 고령자의 디지털 신뢰·접근성 문제로, **창의성 및 AI 활용 적절성**에는 AI의 문맥 이해와 결정론적 권한통제를 결합한 구조로, **실현 가능성 및 완성도**에는 동작 중인 Trust Check 프로토타입·Kiosk UX 원본·공통 AIProvider 설계·fallback 테스트와 CI 결과로 대응한다. 장기적으로는 문자와 키오스크를 시작으로 예약·행정·생활지원·가족 연결까지 확장해, 단순 챗봇이 아니라 **안심하고 일을 맡길 수 있는 시니어 AI 생활매니저**로 발전시키는 것이 목표다.
