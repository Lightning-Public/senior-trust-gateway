# Product Brief — Senior Trust Gateway

## 1. Problem

고령층을 위한 AI 서비스가 늘어날수록 기능 자체보다 **누구를 믿고 어떤 행동을 맡겨도 되는지**가 더 중요한 문제가 된다.

범용 AI가 예약, 검색, 메시지, 공공업무를 잘 처리하더라도 사용자는 다음을 판단해야 한다.

- 이 연락은 진짜인가?
- AI의 답을 믿어도 되는가?
- 어디까지 AI에게 맡겨도 되는가?
- 문제가 생기면 누가 책임지고 이어받는가?

## 2. Product thesis

Senior Trust Gateway는 시니어와 AI/디지털 서비스 사이에 위치하는 **신뢰 게이트웨이**다.

생활매니저 기능을 처음부터 모두 구현하지 않는다. 먼저 사용자를 보호해 신뢰를 만든 후, 검증된 업무부터 위임 범위를 넓힌다.

> **Protect → Trust → Delegate**

## 3. Initial value proposition

> “무언가 하기 전에 먼저 물어보세요. 위험하면 멈추고, 확실하지 않으면 가족이나 사람에게 확인해 드립니다.”

## 4. Primary users

### Senior user

복잡한 디지털 절차와 사기/오인 위험에서 보호받고 싶은 사용자.

### Trust supporter

부모·가족의 모든 디지털 업무를 대신하기는 어렵지만 중요한 순간에는 개입하고 싶은 자녀·보호자·생활지원자.

## 5. Initial wedge

첫 진입 문제는 **의심스러운 문자·링크·전화·요청 확인**이다.

이유:

- 생활에서 자주 발생한다.
- 신뢰 문제를 직접 해결한다.
- 사용자가 AI에게 먼저 찾아올 이유가 생긴다.
- 이후 예약/공공업무/생활대행으로 자연스럽게 확장 가능하다.

## 6. Product moat candidates

모델 자체를 해자로 보지 않는다. 장기 방어력은 다음 조합에서 만든다.

- 사용자별 권한 정책
- 가족/보호자 Trust Circle
- 신뢰할 수 있는 공식 데이터 소스 연결
- 실제 해결 이력과 선호 컨텍스트
- AI ↔ 사람 간 문맥 보존
- 위험 행동을 막는 검증/승인 프로토콜

## 7. Non-goals for Phase 0

- 범용 챗봇 만들기
- 모든 생활서비스 직접 구축
- 독자 LLM 개발
- 의료진/변호사/금융전문가 역할 대체
- 모든 요청을 브라우저 에이전트로 자동 실행

## 8. Success signal

초기 성공은 기능 수가 아니라 다음 질문으로 측정한다.

> 사용자가 중요한 디지털 행동을 하기 전에 자발적으로 Senior Trust Gateway에 먼저 확인하는가?
