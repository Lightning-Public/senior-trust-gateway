# Trust Model

## 목적

이 문서는 AI가 사용자를 대신해 행동할 때 **무엇을 자동으로 하고, 무엇을 확인하고, 무엇을 멈춰야 하는지**에 대한 초기 모델이다.

## Trust Circle

사용자는 자신이 신뢰하는 사람 또는 기관을 등록할 수 있다.

예시:

- 본인
- 자녀/가족
- 생활지원사
- 지정 상담원
- 필요한 경우 전문기관

AI는 신뢰원이 아니라 **신뢰 관계를 관리하고 안전하게 연결하는 중개자**다.

## Risk tiers

### LOW — Assist

예:

- 받은 메시지의 쉬운 설명
- 일정 조회
- 공개 정보 검색
- 사용자가 제공한 정보 정리

정책: 자동 수행 가능. 결과와 근거를 간단히 보여준다.

### MEDIUM — Confirm

예:

- 예약 변경
- 외부에 메시지 전송
- 새로운 서비스 가입 직전
- 되돌릴 수 있지만 타인에게 영향을 주는 행동

정책: 실제 실행 전에 사용자에게 무엇을 할지 확인한다.

### HIGH — Protect / Escalate

예:

- 송금·결제
- 계약/동의
- 계정 비밀번호·인증번호 제공
- 신분증/민감정보 전달
- 원격제어 앱 설치 요청
- 사기 가능성이 있는 낯선 상대의 요구

정책:

1. 자동 실행하지 않는다.
2. 위험 이유를 쉬운 말로 설명한다.
3. 공식 근거로 추가 검증할 수 있으면 확인한다.
4. 필요하면 Trust Circle에 에스컬레이션한다.
5. 검증되지 않으면 안전한 중단을 기본값으로 한다.

## Confidence is not permission

모델의 높은 확신도는 사용자 권한을 대체하지 않는다.

`AI confidence ≠ user authorization`

예를 들어 AI가 특정 결제가 정상이라고 99% 판단해도 결제 권한이 없는 경우 직접 실행하지 않는다.

## Explainability for seniors

위험도 점수만 표시하지 않는다. 가능한 경우 세 단계로 단순화한다.

- 🟢 **괜찮아 보여요** — 확인된 이유 설명
- 🟡 **한 번 더 확인할게요** — 부족한 정보와 확인 방법 설명
- 🔴 **지금은 하지 마세요** — 구체적인 위험 신호 설명

색상만으로 의미를 전달하지 않고 텍스트·음성으로도 동일한 의미를 제공한다.

## Audit trail

중요한 행동에는 최소한 다음을 남길 수 있어야 한다.

- 사용자의 원래 요청
- 판단한 위험등급
- 사용한 근거/데이터 소스
- 사용자 또는 신뢰원의 승인 여부
- 실제 실행된 행동

민감정보 최소수집 및 보존기간은 별도 개인정보 설계 단계에서 정의한다.
